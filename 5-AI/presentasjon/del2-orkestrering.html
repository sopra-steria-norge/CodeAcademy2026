👉 Velg det enkleste som løser oppgaven. Flere agenter = flere ting som kan gå galt, og høyere kostnad.






  

    

      
Mønster 1

      
🔁 Agent loop

      
Én agent i løkke — tenk → verktøy → observer — til oppgaven er løst. Grunnmønsteret alt annet bygger på.

      
Krav: tydelig stoppbetingelse («alle tester grønne») og et tak på antall forsøk.

    

    
  






  

    

      
Mønster 2

      
⛓️ Prompt chaining

      
Faste steg i fast rekkefølge. Output fra ett steg er input til neste — med sjekkpunkter underveis.

      
💡 Workflow-skillen fra del 1 er dette mønsteret.

    

    
  






  

    

      
Mønster 3

      
🔀 Routing

      
En agent klassifiserer oppgaven og sender den til riktig spesialist.

      
🐞 Bugrapport → debugger · ✨ Featureønske → planner

    

    
  






  

    

      
Mønster 4

      
⚡ Parallellisering

      
Fan-out / fan-in: uavhengige deloppgaver kjører samtidig, resultatene samles til slutt.

      
3 reviewere med ulikt fokus: 🔐 sikkerhet · 🚀 ytelse · 📖 lesbarhet
I Copilot CLI: /fleet

    

    
  






  

    

      
Mønster 5

      
🎼 Orchestrator–workers

      
Orkestratoren bryter ned oppgaven dynamisk, delegerer og setter sammen resultatet.

      
Passer når du ikke vet på forhånd hvilke deloppgaver som trengs.

    

    
  






  

    

      
Mønster 6

      
🔄 Evaluator–optimizer

      
Én agent lager, en annen vurderer etter klare kriterier. Løkken går til kriteriene er oppfylt — eller taket er nådd.

      
⌨️ implementer ↔ 🔍 reviewer, maks 3 runder — så spør et menneske.

    

    
  






  
Hvilket mønster? 🧩

  

    
Oppgaven er liten og tydelig🔁 Agent loop

    
Alltid de samme stegene⛓️ Prompt chaining

    
Ulike typer oppgaver som krever ulik ekspertise🔀 Routing

    
Delbar i uavhengige biter⚡ Parallellisering

    
Stor og uoversiktlig🎼 Orchestrator–workers

    
Kvaliteten kan måles🔄 Evaluator–optimizer

  

  
👆 La salen gjette før du klikker

Hook som stopper farlige kommandoer

  

    

      
.github/hooks/guardrails.json

      

{
  "version": 1,
  "hooks": {
    "preToolUse": [
      { "type": "command", "matcher": "bash",
        "bash": "./.github/hooks/guard.sh",
        "timeoutSec": 10 }
    ]
  }
}
      

      
guard.sh svarer på stdout:

      

{"permissionDecision": "deny",
 "permissionDecisionReason": "Force push er ikke tillatt"}

Best practices for trygg bruk

  

    
🔑
Hemmeligheter
Aldri .env, nøkler eller sertifikater.

    
🏢
Kundedata
Følg kundens og Sopra Sterias retningslinjer.

    
⛔
Ingen --yolo
--allow-all kun i isolert sandbox.

    
🛑
Stopp­betingelser
Alle løkker: maks runder + tydelig kriterium.

    
👀
Stol, men verifiser
Tester og review — også når alt «er grønt».

    
🔐
Fremmede skills
Les dem før bruk — særlig skript og allowed-tools.

    
🔎
Sikkerhets­review
Hooks og allow-lister er sikkerhetskontroller.

    
🛡️
Lag på lag
Ingen enkelt guardrail er nok.
